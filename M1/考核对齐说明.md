## 三、展示指南 vs 详细 README：现场动作的差异与覆盖

### M1-1（3 分钟）

| 展示指南动作 | 详细 README | 我们 | 状态 |
| :-- | :-- | :-- | :-- |
| 起 A/B/C 三节点 | 同 | `ros2 run smartcar_m1 {node_a_sensor,node_b_filter,node_c_alarm}` | √ |
| `ros2 interface show sensor_interfaces/msg/SensorData` | 有接口契约但没要求现场展示 | 包名/字段名/顺序完全按契约 | √ 实测 |
| `/processed_distance` 约 10 Hz | 同 | 10.001 Hz | √ |
| `param set /node_b_filter alpha 0.9` 要明显变"跳" | 同 | 参数名正是 `alpha`，回调里生效 | √ 实测 |
| 调一次报警 + 停服务端后触发出现超时 | 同 | **必须带 `-p serve_alarm:=false` 并单独起 `alarm_server`**，否则节点 C 自带服务端，杀不掉，永远不超时 | √ 实测 1.05 s |
| 提前准备一条 `status=1` 消息并解释 | 只要求"打印警告、不参与滤波" | `ros2 topic pub --once … status: 1` → `[DROP] 丢弃无效数据 status=1(超出量程)` | √ 实测 |

> 这条差异是**最容易翻车的点**：展示指南默认"服务端是外部进程"，我们的默认值 `serve_alarm:=true` 是"节点 C 自带服务端"。现场一定要按演示清单那样起。

### M1-2（4 分钟）

| 展示指南动作 | 详细 README | 我们 | 状态 |
| :-- | :-- | :-- | :-- |
| **一条 launch 起 robot1**，再用**同一个 launch** 起 robot2、两份 YAML 各自加载 | 一条命令起两组 | 两种入口都支持：`second_namespace:=`（单组）跑两次；或 `params_file2:=…` 一条起两组 | √ 实测单组两次 |
| 查 `/robot1/node_c_alarm` 与 `/robot2/node_c_alarm` 的 `alarm_threshold` | 同 | 0.3 / 0.5 | √ |
| `ros2 topic list` 展示隔离 | 同 | `/robot1/processed_distance`、`/robot2/processed_distance` | √ |
| 用不存在的参数文件路径启动，展示报错 | 同（要求不栈回溯） | `OpaqueFunction` 先校验 → `LogInfo` + `EmitEvent(Shutdown)`，`grep Traceback`=0 | √ |
| **改一组 alpha 看另一组是否被带偏**（新增） | 未提 | `/robot1/node_b_filter alpha=0.9` 后 `/robot2/…` 仍 0.6 | √ 实测 |

### M1-3（5 分钟）
